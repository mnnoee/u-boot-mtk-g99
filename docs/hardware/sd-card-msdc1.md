## ЧТО не работает / The symptom

| | |
|---|---|
| Контроллер | **MSDC1** (в форках MTK — `sdhc2`), база **`0x11240000`** |
| Прерывание | `GIC_SPI 135` |
| Карта в телефоне | microSD, 4-бит, есть |
| **Симптом** | `mmc info` не выводит данных о карте |
| **Что видно в логе** | `CRCERR`, `INT = 0x480` |
| **Эталон (Android)** | `CMD8` → `0x1aa` с первой попытки |

Ключевое наблюдение: **контроллер запускается, команда уходит, карта не отвечает.**

- `CMD0` (без ответа) проходит отлично — `INT=0x180` (CMDRDY)
- `CMD8` (ожидаем ответ) — `INT=0x400`, `RSP=0`, то есть ответа нет
- По поллеру v219: во второй попытке `CMD=1` (`0x1010002`) на первых сэмплах, потом
  линии прижимаются к нулю. В первой попытке `DAT0` поднимается к сэмплу 2–3 —
  **линия живая, но ответа нет**

## С чем сравнивали / Reference

Всё сверялось с **живым Android**, где карта работает:

| Источник | Что взято |
|---|---|
| `/sys/firmware/fdt` | реальные `compatible`-строки |
| `/sys/kernel/debug/*`, `/sys/class/*` | состояние контроллера |
| живой дамп регистров | bind-эталоны (до и после команд) |
| декомпилированный LK | последовательность инициализации 1:1 |
| `.ko` модуль вендора | раскладка регистров (`mtk-mmc.h`) |

> ⚠️ **Важный вывод разбора:** «отличия» `PATCH_BIT1 = 0xffe64309` и `DTOC`
> оказались **ложными следами** — они наблюдаются только 1–2 мс при reset
> (autok-тюнинг вендора), а не как реальные расхождения.
>
> **Key finding:** the apparent `PATCH_BIT1` and `DTOC` differences are **red
> herrings** — they only appear for 1–2 ms during reset (vendor auto-tuning).

## Хронология попыток / Experiment log

Каждая строка — коммит в `drivers/mmc/mtk-sd.c`. **Не повторять.**

| Версия | Что меняли | Результат |
|---|---|---|
| **v161** | исправлен маппинг ID часов в topckgen, маркеры в probe | CLK настроены, карта не видна |
| **v162** | отключено включение `h_clk` | обход зависания шины `infra_ao1` |
| **v168** | отключены **все** гейты `infra_ao` в `ungate_clock` | обход зависания шины |
| **v174** | флаг `MMC_BROKEN_CD` — всегда «карта есть» | костыль, карта всё равно не отвечает |
| **v175–v176** | отладочная печать в `mmc_get_op_cond` | печать ломает USB-перечисление → откат в v177 |
| **v177** | отладочная печать удалена | USB снова работает |
| **v178** | режим пинов MSDC1 в probe драйвера | без эффекта |
| **v179** | полный pinctrl MSDC1 (mode + IES + SMT + PUPD + R0/R1) | линии живые, ответа нет |
| **v189** | **обнаружение** карты: гейты через CLR + полярность CD | `mmc info` перестал врать, но карты нет |
| **v191** | pwrap init + реальные питания PMIC (2.9 В / 1.8 В), MSDC1 src = 192 МГц | ⚠️ 26 МГц был **ошибкой** — на шине 2.8 кГц вместо 400 кГц |
| **v214** | последовательность LK 1:1, живые значения Android: `PATCH_BIT 0x403c0007 / 0xfffe4340 / 0x3488180f`, `ADV_CFG0 0x3808c169`, `EMMC51_CFG0 0x2d000000`, `TOP ENH_EN`, `PAD_TUNE=0`, 100 кГц, pinctrl вендора (CLK pull-down, DRV=3), `r_smpl=1` | CRCERR |
| **v218** | `PATCH_BIT2 = 0x2D0B4000` (биты 8,12 как у Android) | CRCERR тот же (`0x480`) |
| **v219** | `f_min` 400 кГц, `r_smpl=0` (как в живом Android), отключён LK eMMC-boot handshake, `PATCH_BIT2 = 0x348a180f`, `EMMC_CFG1 = 0x2d0b4000`, `async_fifo_crcsts` + `enhance_rx`, команда `msdcbg` | CRCERR тот же. **Регистры 1:1 с эталоном bind-эталона Android** |

### Что уже исключено / Ruled out

| Фактор | Проверено | Итог |
|---|---|---|
| `f_min` | 100 / 200 / 400 кГц | **не влияет** |
| `r_smpl` (RSPL) | 0 и 1 | **не влияет** |
| `DTOC` | 2 и 3 (вендор ставит 3) | **не влияет** |
| `PATCH_BIT2` | `0x3488180f`, `0x348a180f`, `0x2D0B4000` | **не влияет** |
| LK eMMC-boot handshake | вкл. / выкл. | **не влияет** |
| Пинмux / подтяжки | полный набор + вендорский pinctrl | линии живы |
| Питание PMIC (pwrap) | 2.9 В / 1.8 В по живому дампу | **не влияет** |
| Тактовая частота | 26 МГц (ошибка) → 192 МГц | исправлено, но не помогло |

> **Вывод v219: статика регистров исчерпана.** Проблема **не** в значениях
> регистров — контроллер настроен 1:1 как в Android, где карта работает.
>
> **Conclusion: static register values are exhausted.** The controller is configured
> 1:1 as in working Android, so the problem is *not* in register values.

## Два оставшихся варианта / Two remaining possibilities

Из заметки `mt6789_msdc1_android_init_phase_2026-08-10`:

1. **Команда физически не доходит до карты** — прижимается к низу, несмотря на живой
   `DAT0` в первой попытке.
2. **Карта отвечает, но контроллер не защёлкивает ответ** — чисто аппаратная
   (или clocksource) проблема.

Различить их — задача следующего шага.

## Следующий шаг / Next step

**Сравнить внутреннее состояние через отладочный мукс MSDC.**

В U-Boot уже есть готовая команда (добавлена в v219):

```bash
msdcbg
```

Она даёт:
- все регистры MSDC1 (`0x00`…`0x228`)
- отладочный мукс: `writel(sel, 0xa0)` → `readl(0xa4)` для `sel = 0..0x63`
- режим `EMMC50_CFG4`: `sel = 0x27`, затем `writel(i, 0x220)` → `readl(0xa4)` для `i = 0..11`

Зеркалит вендорский `msdc_dump_dbg_register()` (`mtk-mmc-dbg.c`).

Текущее состояние в U-Boot: `sel 0x07 = 1`, `sel 0x19 = 1`, остальные нули.

**Что сделать:**

1. Снять `msdcbg` на **живом Android** с вставленной картой (там она работает) —
   сопоставить с `/sys/kernel/debug/` или модулем `mtk-mmc-dbg`.
2. Снять `msdcbg` в U-Boot с той же картой.
3. Сравнить по битам — разница укажет, где расходится внутреннее состояние.

Команда в U-Boot (вручную, если `msdcbg` не собран):

```
writel 0x112400a0 0x07
md.l 0x112400a4 1
```

## Известные грабли / Known traps

| Грабли | Что делать |
|---|---|
| Отладочная печать ломает USB-перечисление | печатать через `early_log` (буфер в памяти), а не `printf` |
| Запись в `CLR`-регистр `0x1000108c` **вешает шину** | не трогать без понимания; `msdc_clock_bus_hang.md` |
| `source = 26 МГц` даёт 2.8 кГц на шине, а не 26 МГц | использовать 192 МГц (`MSDCPLL`) |
| LK eMMC-boot handshake может держать CMD/DAT прижатыми | в v219 отключён, но не помогло |
| `simple-framebuffer` по DT → Synchronous Abort | см. [`display.md`](display.md) |

## Ранний лог / Early log

Все `EARLY_W`/`EARLY_WF` пишут в буфер по `0x43FFF000` (16 МБ) — читается после
загрузки U-Boot, когда обычная консоль ещё не работает:

```bash
# в консоли U-Boot
md.b 0x43fff010 800
```
