# Дисплей / Display

**Статус: ✅ работает.** Текст U-Boot выводится на AMOLED 1080×2400.
**Status: ✅ working.** U-Boot text renders on the 1080×2400 AMOLED.

---

## ЧТО / What

| | |
|---|---|
| Панель / Panel | ILI7835F |
| Интерфейс / Interface | DSI, 2 канала |
| Разрешение / Resolution | 1080 × 2400 |
| Формат / Format | ARGB8888, 32 бит/пиксель |
| Шаг строки / Stride | 1080 × 4 = **4320 байт** |
| Размер буфера / Buffer size | 4320 × 2400 = **10 368 000 байт** (~9.9 МиБ) |
| Адрес буфера / FB address | `0xfeabe000` — то, что ставит LK (см. § «Два адреса») |
| Резерв в DT | `framebuffer@fe0c8000`, `0x1f2f000` (31 МиБ) |
| Диапазон памяти / Memory | MMSYS `0x14000000` |

### Два адреса — не путайте / Two addresses, do not confuse

| Адрес | Что это | Откуда |
|---|---|---|
| `0xfe0c8000` | **начало зарезервированной области** в `reserved-memory` | реальный DT телефона |
| `0xfeabe000` | **адрес кадра, который поставил LK**, и дефолт драйвера | читается из `OVL0_L0_ADDR` |

`0xfeabe000` лежит **внутри** резерва `0xfe0c8000…0xfffb7000` — конфликта нет,
но путать их легко. Драйверу важен тот адрес, который реально стоит в `OVL0_L0_ADDR`.

## Кто чем занимается / Who does what

Главная особенность: **DSI-контроллер и панель инициализирует не U-Boot, а LK**,
который грузится раньше. Наш драйвер не инициализирует панель заново — он
перенастраивает только тракт передачи кадра.

| Блок / Block | База / Base | Кто настраивает / Configured by |
|---|---|---|
| `MMSYS` | `0x14000000` | наш драйвер — гейты, сброс, мультиплексоры |
| `MUTEX0` | `0x14001000` | наш драйвер — блокировки |
| `OVL0` | `0x14005000` | наш драйвер — слой 0, адрес кадра |
| `RDMA0` | `0x14007000` | наш драйвер — чтение кадра из DRAM |
| `DSI0` | `0x14013000` | **LK** — тайминги, PLL, сам DSI |
| Панель ILI7835F | через DSI | **LK** — команды инициализации панели |

```
   framebuffer (0xfeabe000, 10.4 МБ)
            │
            ▼
        OVL0  ──── слой 0: адрес, размер, формат
            │     выход через MUTEX0
            ▼
       RDMA0  ──── читает пиксели из DRAM
            │
            ▼
      DITHER0 ──── преобразование в формат панели
            │
            ▼
        DSI0  ──── уже настроен LK, шлёт команды в панель
            │
            ▼
      ILI7835F ─── AMOLED 1080×2400
```

## ПОЧЕМУ свой драйвер / Why a custom driver

| Проблема / Problem | Решение / Solution |
|---|---|
| В форке **нет** DRM-драйвера для MT6789 — ни `mtk_disp`, ни панельных драйверов | Написан минимальный драйвер `UCLASS_VIDEO` — 453 строки |
| `simple-framebuffer` из DT приводил к **Synchronous Abort**: адрес `0xfe0c8000` не отображён в MMU U-Boot | Узел с `compatible = "simple-framebuffer"` **удалён из DTS** (в отличие от `mt6789-motorola-vicky.dts` и `mt8781-zinwa-xelex.dts` форка, где он есть). Область `0xfe0c8000` осталась в `reserved-memory` — но **без `no-map`**, чтобы U-Boot мог к ней обращаться |
| DSI полностью настроен LK — повторная инициализация ломала картинку (пробовал `reset + CMDQ_SIZE 0x0001 + CON_CTRL DSI_EN`) | Триггер оставлен как в v183: `CMDQ_SIZE 0x8001` + переключение `DSI_START` |
| `OVL0 SRC_CON` был `0x3` (два слоя от LK) | Ставится `0x3` — слой 0 + слой 1, LK оставил их активными |
| `OVL0 L0_CON = 0x1001020` не подходил для ARGB8888 | Заменён на `0x000001ff` — 32 бита, разрешение 1080×2400 |

## Как устроен драйвер / How the driver works

### Порядок инициализации / Init sequence

1. **Проверка MMIO** — читаем `MMSYS_EN`, если недоступно, выходим.
2. **Определение адреса кадра**:
   ```c
   fb_phys = readl(OVL0_L0_ADDR);
   if (!fb_phys || fb_phys == 0xffffffff)
           fb_phys = LK_DEFAULT_FB;   /* 0xfeabe000 */
   ```
3. **Проверка диапазона** — вне `0x40000000 … 0x2fffffffff` → откат на `LK_DEFAULT_FB`.
4. **Настройка конвейера** — гейты, сброс, мультиплексоры, слой 0, RDMA0.
5. **Отрисовка** — vidconsole рисует символы, затем `dsync` шлёт кадр через DSI.

### Ключевые регистры / Key registers

| Регистр | Адрес | Зачем |
|---|---|---|
| `MMSYS_CLK_CLR` | `0x14000108` | снять гейт (управление через **CLR**, не SET) |
| `MMSYS_SW_RST` | `0x14000140` | write-1-to-deassert |
| `MMSYS_CFG_UPDATE` | `0x1400f0c` | загрузка теневых настроек мультиплексоров |
| `MMSYS_OVL0_MOUT` | `0x1400f18` | выход OVL0 |
| `MMSYS_RDMA0_SEL_IN` | `0x1400f28` | вход RDMA0 |
| `MMSYS_DITHER0_MOUT` | `0x1400f20` | выход DITHER0 |
| `MMSYS_DSI0_SEL_IN` | `0x1400f30` | вход DSI0 |
| `OVL0_EN` | `0x14005000` | бит 22 — теневой перезапуск |
| `OVL0_SRC_CON` | `0x1400502c` | включение слоёв |
| `OVL0_L0_ADDR` | `0x14005f40` | адрес кадра в DRAM |
| `DSI0_START` | `0x14013000` | бит 0 — запуск передачи |
| `DSI0_CMDQ_SIZE` | `0x14013060` | биты [5:0] — счётчик, бит 15 — запуск |
| `DSI0_CMDQ` | `0x14013d00` | **FIFO команд — для MT6789 это `0xd00`, а не `0x200`** |

### Кэш обязателен / Cache flush is mandatory

> ⚠️ OVL читает кадр **из DRAM**. `mw.l` пишет только в кэш CPU.
> Без `dc cvac` экран останется пустым.

```bash
# в U-Boot, после записи в кадр — драйвер делает это сам, вручную:
dc cvac 0xfeabe000 0xa3e000    # или цикл по 64-байтным строкам
```

Драйвер вызывает `flush_dcache_range()` — при ручной записи в кадр
(`mw.l`) нужно делать `dc cvac` самому.

## Диагностика / Diagnostics

После `probe()` драйвер пишет блок «магических» значений в память **сразу за кадром**:

| Адрес | Что |
|---|---|
| `0xff4a1400` | база диагностического буфера (`LK_DEFAULT_FB + DISP_FB_SIZE`) |
| `+0x00` | magic `0xDEADBEEF` |
| `+0x04` | `uc_priv->fb` |
| `+0x08` | `plat->base` |
| `+0x0c` | `uc_priv->fb_size` |

Читается **после загрузки U-Boot**, в консоли:

```bash
md.l 0xff4a1400 20
```

Если `magic` не `0xDEADBEEF` — драйвер не дошёл до конца `probe()`, смотрите
сообщения в консоли ACM.

## Известные проблемы / Known issues

| Симптом | Причина | Статус |
|---|---|---|
| Пустой экран | не сделан `dc cvac` после записи в кадр | ✅ решено в драйвере |
| `Synchronous Abort` при старте | `simple-framebuffer` `0xfe0c8000` не отображён в MMU | ✅ узел удалён из DTS |
| Артефакты, двоится текст | не применён `CFG_UPDATE` после мультиплексоров | ✅ вызывается в драйвере |
| Логотип LK поверх текста U-Boot | LK не очистил слои | ✅ `OVL0_SRC_CON` = `0x3` |
